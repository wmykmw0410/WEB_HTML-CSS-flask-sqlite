# Webページが表示されるしくみ

> 補足資料（[00_docs](../)）

「URLを入力してから、ページが画面に表示されるまで」に何が起きているのかをまとめた資料です。ここで扱う言葉（リクエスト・レスポンス・URL・ステータスコードなど）は、フロントエンド編・バックエンド編のあちこちで出てきます。章のように順番に読む必要はありません。わからない言葉が出てきたときに、該当する節を読んでください。

バックエンド編を始めるのに必要な最低限の内容は、[02_backend/01_intro](../../02_backend/01_intro/#webのしくみ最低限)の冒頭にも短くまとめています。

コードは書きません。最後の節で、ブラウザの開発者ツールを使って、実際の通信を目で見て確かめます。

サーバーの内部の仕組み（Webサーバー・APサーバー・データベース、Cookieとセッションなど）はバックエンド編で扱います。

## 1. Webページが表示されるまで

Webページは、**ブラウザ**（Chrome・Safari・Edge・Firefoxなど）が**サーバー**（インターネットの向こうにあるコンピュータ）にお願い（**リクエスト**）を送り、サーバーが返事（**レスポンス**）を返すことで表示されます。

```
ブラウザ ──(リクエスト：このページをください)──▶ サーバー
ブラウザ ◀──(レスポンス：HTMLです)───────────── サーバー
```

| # | 処理 | 担当 |
|---|---|---|
| 1 | ユーザーがURLを入力する（またはリンクをクリックする） | ユーザー |
| 2 | URLのドメイン名から、サーバーの住所（IPアドレス）を調べる（8節） | ブラウザ |
| 3 | サーバーにリクエストを送る | ブラウザ |
| 4 | サーバーがHTMLをレスポンスとして返す | サーバー |
| 5 | ブラウザがHTMLを読み、必要なCSS・JavaScript・画像を**さらにリクエストする** | ブラウザ |
| 6 | 受け取ったHTML・CSSから画面を組み立てて表示し、JavaScriptを実行する | ブラウザ |

5番のとおり、1つのページを表示するだけでも、HTML・CSS・画像などの**複数のリクエスト**が送られています。HTMLに`<link rel="stylesheet" href="style.css">`や`<img src="...">`と書くと、ブラウザがそのファイルを別にリクエストします（01_html_basics・03_css_basicsで書く内容です）。

## 2. フロントエンドとバックエンド

| 区分 | 動く場所 | 主な技術 | 役割 | このカリキュラム |
|---|---|---|---|---|
| フロントエンド | ブラウザ（利用者の手元） | HTML・CSS・JavaScript | 画面の表示・操作への反応 | [フロントエンド編](../../01_frontend/) |
| バックエンド | サーバー | Python（Flask）・データベースなど | データの保存・ログイン・計算などの処理 | [バックエンド編](../../02_backend/) |

フロントエンド編で作るオリジナルHPは、HTML・CSS・JavaScriptのファイルを**そのまま返すだけ**のサーバーがあれば動きます。メモ帳アプリでデータを保存したり、ログインした人だけに見せたりするには、バックエンドが必要になります。

## 3. URLの構造

```
https://example.com:443/blog/index.html?page=2#comments
└─┬─┘   └────┬────┘└┬┘└──────┬──────┘└──┬──┘└───┬───┘
スキーム  ドメイン  ポート    パス      クエリ  フラグメント
```

| 部分 | 意味 | フロントエンド編で出てくる場面 |
|---|---|---|
| スキーム | 通信の方法。`https`（暗号化あり）・`http`・`file`（自分のパソコンのファイル）など | 10_js_data：`file://`で開いたページでは`fetch()`が使えない |
| ドメイン（ホスト名） | 接続先のサーバーの名前。`localhost`は自分のパソコンを指す | 10_js_data：`http://localhost:8000` |
| ポート | サーバーの中のどの窓口につなぐかの番号。`https`なら443、`http`なら80が省略されている | 10_js_data：`python -m http.server 8000`の`8000` |
| パス | サーバーの中のどのファイル（ページ）か | 01_html_basics：相対パス・絶対パスでのリンク |
| クエリ | サーバーやページに渡す追加の情報。`?キー=値&キー=値` | 02_backend/02_memo_app_frontend：`edit.html?id=3` |
| フラグメント | ページ内の場所（`id`）。サーバーには送られない | 01_html_basics：ページ内リンク`#images` |

## 4. リクエストとレスポンス

ブラウザとサーバーのやり取りは、**HTTP**という決まりに従った文字のメッセージです。

リクエストの例：

```
GET /index.html HTTP/1.1
Host: example.com
```

レスポンスの例：

```
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8

<!doctype html>
<html>...</html>
```

| 部分 | 役割 | 例 |
|---|---|---|
| 1行目 | リクエストは「**メソッド**・パス」、レスポンスは「**ステータスコード**」 | `GET /index.html` ／ `200 OK` |
| ヘッダー | 付加情報（`名前: 値`の形） | `Content-Type: text/html`（中身がHTMLであること） |
| ボディ | 中身そのもの | HTML・CSS・画像・JSONなど |

**メソッド**は「何をしたいか」を表します。フロントエンド編で出てくるのは次の2つです。

| メソッド | 意味 | 出てくる場面 |
|---|---|---|
| GET | ページやデータを**取得する**。アドレスバーへの入力・リンクのクリック・`fetch()`の初期設定はすべてGET | 02_html_semantic_form：`<form method="get">`は入力内容がURLのクエリになる |
| POST | データを**送る** | 02_html_semantic_form：`<form method="post">`は入力内容がボディに入る（受け取るのはバックエンド編） |

このほかにも、データを**更新する**・**削除する**ためのメソッドがあります。フロントエンド編では[10_js_data](../../01_frontend/10_js_data/#6-httpメソッドを体験するjsonplaceholder発展任意)の6節（発展・任意）で、練習用のAPIに送って体験できます。データを本当に保存・削除するサーバーは、バックエンド編で自分で作ります。

| メソッド | 意味 | 出てくる場面 |
|---|---|---|
| PUT | データを**丸ごと置き換える**（更新） | 02_backend/08_request |
| PATCH | データの**一部だけを変える**（更新） | 10_js_data 6節（体験のみ。バックエンド編ではPUTを使う） |
| DELETE | データを**削除する** | 02_backend/08_request |

データに対する4つの基本操作（**CRUD**：Create・Read・Update・Delete）は、メソッドと次のように対応します。

| 操作 | メソッド | 例（メモ帳アプリ） |
|---|---|---|
| Create（作成） | POST | `POST /api/memos`：メモを追加する |
| Read（読み取り） | GET | `GET /api/memos`：メモの一覧を取得する |
| Update（更新） | PUT | `PUT /api/memos/3`：3番のメモを書き換える |
| Delete（削除） | DELETE | `DELETE /api/memos/3`：3番のメモを削除する |

HTMLのフォーム（`<form method="...">`）で送れるのはGETとPOSTだけです。PUT・DELETEのリクエストは、JavaScriptの`fetch()`（10_js_dataで学びます）で送ります。

**Content-Type**は、レスポンスの中身の種類をブラウザに伝えるヘッダーです。`text/html`・`text/css`・`application/javascript`・`image/png`・`application/json`（10_js_dataで扱うJSON）などがあります。

## 5. ステータスコード

レスポンスの1行目には、リクエストの結果を表す3桁の**ステータスコード**が必ず入っています。

| 分類 | 意味 |
|---|---|
| 2xx | 成功 |
| 3xx | 別の場所へ移動（リダイレクト） |
| 4xx | リクエストする側（ブラウザ・URL）の問題 |
| 5xx | サーバー側の問題 |

フロントエンド編でよく見るのは次の3つです。

| コード | 意味 | 見る場面 |
|---|---|---|
| 200 OK | 成功 | ほとんどのリクエスト |
| 404 Not Found | ファイル（ページ）が見つからない | リンクや`src`のパスの打ち間違い・10_js_dataで存在しないJSONを読み込んだとき |
| 304 Not Modified | 前回から変わっていないので、ブラウザに保存してある分を使ってよい | 同じページを再読み込みしたとき |

画像が表示されない・CSSが効かないときは、10節のNetworkタブでそのファイルが**404**になっていないかを確認するのが近道です。より詳しいステータスコードはバックエンド編の[04_flask_basic](../../02_backend/04_flask_basic/)で扱います。

## 6. HTTPとHTTPS

| | 説明 |
|---|---|
| HTTP | ブラウザとサーバーのやり取りの決まり。中身は暗号化されない |
| HTTPS | HTTPの通信を**暗号化**したもの。途中で盗み見られたり、書き換えられたりするのを防ぐ |

今のWebサイトは、ほぼすべてHTTPSです。ブラウザのアドレスバーに鍵のマークが表示されます。11_homepageの補足で使うGitHub Pagesも、自動でHTTPSになります。

自分のパソコンの中だけで確認するとき（`http://localhost:8000`）は、通信が外に出ないのでHTTPのままで問題ありません。

## 7. 静的サイトと動的サイト

| 種類 | 特徴 | 例 | このカリキュラム |
|---|---|---|---|
| 静的サイト | 誰が見ても同じファイル（HTML・CSS・JavaScript・画像）を返す | 会社案内・ポートフォリオ | フロントエンド編のオリジナルHP |
| 動的サイト | 見る人や条件によって、サーバーがその場でページを作って返す | ログインが必要なサービス・ECサイト・SNS | バックエンド編のメモ帳アプリ |

静的サイトでも、JavaScriptを使えばブラウザの中で動きを付けられます（05_js_basics以降）。ただし、データを他の人と共有したり、ログインした人だけに見せたりするには、動的サイト（バックエンド）が必要です。

## 8. ドメインとDNS

**ドメイン**は、`example.com`のような、サーバーに付けられた覚えやすい名前です。コンピュータ同士は、本当は**IPアドレス**（`93.184.215.14`のような数字の住所）で通信しています。ドメイン名からIPアドレスを調べる仕組みを**DNS**と呼びます（1節の2番）。

```
ブラウザ「example.com の住所は？」 ──▶ DNSサーバー
ブラウザ ◀── 「93.184.215.14 です」
ブラウザ ──(リクエスト)──▶ 93.184.215.14 のサーバー
```

11_homepageの補足でHPを公開すると、`ユーザー名.github.io`というドメインでアクセスできるようになります。IPアドレスについては次の9節で扱います。

## 9. IPアドレス

インターネットにつながる機器には、それぞれ**IPアドレス**という番号が割り当てられています。8節のDNSで調べていたのも、このIPアドレスです。広く使われているIPv4は、0〜255の数を4つ並べた形です（例：`192.168.0.1`）。

### プライベートIP / グローバルIP

| 種類 | 範囲の例 | 特徴 |
|---|---|---|
| プライベートIP | `192.168.0.0〜192.168.255.255`、`10.0.0.0〜10.255.255.255` など | 家庭内LANや社内LANなど、限られた範囲の中だけで使う。別の家で同じアドレスが使われていてもよい |
| グローバルIP | 上記以外 | インターネット上で世界に1つだけ。プロバイダから割り当てられる |
| ループバック | `127.0.0.1`（`localhost`） | 自分自身を指す特別なアドレス。10_js_dataの`http://localhost:8000`や、バックエンド編のFlaskの開発用サーバーで使う |

家庭のルーターは1つのグローバルIPを持ち、その内側にいる各端末（PC・スマホなど）にはルーターがプライベートIPを割り振っています。1つのグローバルIPを複数の端末で共有してインターネットに出る仕組みを、NATといいます。

### 確認コマンド

| 目的 | コマンド | OS |
|---|---|---|
| 自分のIPアドレスを確認する | `ipconfig getifaddr en0` | Mac |
| 自分のIPアドレスを確認する | `ip a` | Linux |
| 自分のIPアドレスを確認する | `ipconfig` | Windows |
| 相手に届くか確認する（疎通確認） | `ping 8.8.8.8` | 共通 |
| ドメイン名からIPアドレスを調べる | `nslookup google.com` | 共通 |
| 通信の経路を確認する | `traceroute 8.8.8.8` | Mac / Linux |
| 通信の経路を確認する | `tracert 8.8.8.8` | Windows |

`traceroute`を実行すると、目的地に届くまでに経由するルーターが1台ずつ表示されます。最初の1〜2つは自宅のルーターなどのプライベートIPで、その先からグローバルIPに変わっていくのが確認できます。

```
traceroute to 8.8.8.8, 5 hops max
 1  192.168.68.1     ← 自宅のルーター（プライベートIP）
 2  192.168.0.254    ← プロバイダ側の機器（プライベートIP）
 3  133.205.169.111  ← ここからグローバルIP
 4  210.147.219.246
 5  133.208.191.41
```

自分のパソコンのプライベートIPがわかると、同じWi-Fiにつないだスマホから、パソコンで動いているサーバーにアクセスできます（[11_homepage](../../01_frontend/11_homepage/#いろいろな環境で見る)の実機確認で使います）。

```bash
python -m http.server 8000 --bind 0.0.0.0   # 0.0.0.0：自分以外の端末からの接続も受け付ける
# → スマホのブラウザで http://（パソコンのプライベートIP）:8000 を開く
```

`localhost`（`127.0.0.1`）は「自分自身」を指すので、スマホで`localhost`を開いても、パソコンではなくスマホ自身を指してしまいます。

## 10. 開発者ツールで通信を見る

ブラウザには、ページの中身や通信を調べる**開発者ツール**が付いています。各パネルの使い方は[01_frontend/01_html_basics](../../01_frontend/01_html_basics/#0-はじめに学習環境と開発者ツール)の0節で詳しく説明しています。ここでは、通信を一覧できる**Network**タブを使ってみます。

| OS | 開き方 |
|---|---|
| Mac | `Cmd + Option + I` |
| Windows | `F12`（または`Ctrl + Shift + I`） |

### 動作確認：実際の通信を見る

| 確認する操作 | 確認したいこと |
|---|---|
| 好きなWebサイトを開き、開発者ツールの**Network**タブを開いてからページを再読み込みする | 1回の表示で、HTML・CSS・JavaScript・画像などの**たくさんのリクエスト**が送られている（1節の5番） |
| 一覧の一番上（ページそのもののHTML）をクリックし、Headersを見る | Request Methodが`GET`、Status Codeが`200`、Response Headersの`Content-Type`が`text/html`になっている（4・5節） |
| アドレスバーで、URLの末尾に存在しないページ名（例：`/not-found-page`）を付けて開く | Networkタブで、そのリクエストのStatusが`404`になっている（5節） |
| もう一度再読み込みする | いくつかのファイルのStatusが`304`になったり、Sizeに`(disk cache)`や`(memory cache)`と表示されたりする（ブラウザに保存してある分を使っている） |
| アドレスバーの鍵マークをクリックする | 「この接続は保護されています」のように、HTTPSで暗号化されていることがわかる（6節） |
