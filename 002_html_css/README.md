## 1. HTMLの基本タグ

> [example/01_basic.html](example/01_basic.html)

```html
<h1>見出し1</h1>
<h2>見出し2</h2>
<p>これは段落です。<a href="https://developer.mozilla.org/ja/">MDN</a>のようにリンクを貼れます。</p>

<ul>
    <li>順序なしリストの項目1</li>
</ul>

<ol>
    <li>順序ありリストの項目1</li>
</ol>

<img src="img/sample.png" alt="サンプル画像" width="150">

<div>
    <p>divは意味を持たない汎用ブロック要素。レイアウトのための箱として使う。</p>
</div>
```

### ポイント

| タグ | 役割 |
|---|---|
| `<h1>`〜`<h6>` | 見出し。数字が小さいほど重要度が高い |
| `<p>` | 段落 |
| `<a href="...">` | リンク |
| `<ul>` / `<ol>` / `<li>` | 順序なし／順序ありリスト |
| `<img src="..." alt="...">` | 画像。`alt`は画像が表示できないときの代替テキスト（アクセシビリティ上必須） |
| `<div>` | 意味を持たない汎用のブロック要素。CSSでレイアウトを組むための「箱」として使う |
| `<span>` | 意味を持たない汎用のインライン要素。文章の一部だけを装飾したいときに使う（`<div>`の行内版） |
| `<table>` / `<tr>` / `<th>` / `<td>` | 表。`<tr>`が行、`<th>`が見出しセル、`<td>`が通常セル |

入力フォーム系のタグ（`<input>`/`<label>`/`<button>`など）は「6. フォームの基本」で扱います。

### 実行方法

`example/01_basic.html` をブラウザで直接開いてください（`ファイルを開く`、またはVS Codeの拡張機能「Live Server」を使うと便利です）。

### 動作確認：基本タグごとの見た目の違い

| 確認する操作 | 確認したいこと |
|---|---|
| `example/01_basic.html`をブラウザで開く | `見出し1`が`見出し2`より大きな文字で表示され、本文中の「MDN」という文字がリンクらしい見た目（下線・青字など）になっている |
| リンク「MDN」をクリックする | 新しいタブ・ページでMDN Web Docsに遷移する |
| `<ul>`と`<ol>`の見た目を見比べる | `<ul>`は黒丸、`<ol>`は`1.`のような数字で項目が表示され、記号の違いで「順序なし／順序あり」を区別できる |
| `<img>`の`src`を存在しないファイル名に一時的に書き換えて保存し、リロードする（確認後は元に戻す） | 画像が表示されなくなり、代わりに`alt="サンプル画像"`の文字が表示される |

**正常な状態の見分け方**：見出しの大小・リストの記号・画像（またはalt文字）が期待通りに表示されていれば正常です。崩れて表示される場合はタグの閉じ忘れなどHTML構文のミスを疑ってください。

## 2. CSSセレクタの基本

> [example/02_selectors.html](example/02_selectors.html)

CSSは「どの要素に」「どんなスタイルを」適用するかを**セレクタ**で指定します。ここまでの`.card`や`.card-grid`のような書き方の意味がここでわかります。

```css
/* 要素セレクタ: すべての <p> に適用される */
p {
    color: red;
}

/* クラスセレクタ: class="highlight" を持つ要素に適用される（. から始まる） */
.highlight {
    background: yellow;
}

/* IDセレクタ: id="title" を持つ要素だけに適用される（# から始まる） */
#title {
    font-size: 32px;
}

/* 子孫セレクタ: .card の中にある <p> だけに適用される */
.card p {
    color: gray;
}
```

```html
<h1 id="title">タイトル</h1>
<p class="highlight">この段落だけ黄色くなる</p>
<div class="card"><p>この段落だけ子孫セレクタの対象になる</p></div>
```

### 使い分け

| セレクタ | 記法 | 使う場面 |
|---|---|---|
| 要素セレクタ | `p { }` | そのタグ全体に共通のスタイルを当てたいとき |
| クラスセレクタ | `.card { }` | 同じスタイルを複数の要素で使い回したいとき（**最もよく使う**） |
| IDセレクタ | `#title { }` | ページ内で1つだけの要素を指定したいとき |
| 子孫セレクタ | `.card p { }` | 「特定の親の中にある要素だけ」に絞りたいとき |

`100_memo_api`のCSSでも、`.card`・`.card-grid`・`.card img`（子孫セレクタ）のように、ほぼクラスセレクタと子孫セレクタだけで組まれています。

### 実行方法

`example/02_selectors.html` をブラウザで開き、それぞれの段落の色が変わることを確認してください。

### 動作確認：セレクタごとに適用範囲が変わっているか

| 確認する操作 | 確認したいこと |
|---|---|
| `example/02_selectors.html`をブラウザで開く | すべての`<p>`が同じフォント（`sans-serif`）で表示される（要素セレクタ`p { }`が全段落に効いている） |
| `.highlight`クラスが付いた段落を見る | その段落だけ黄色っぽい背景（`#fff3cd`）が付いている（クラスセレクタは指定した要素だけに効く） |
| `id="title"`の見出し（`CSSセレクタの基本`）を見る | その見出しだけ青色（`#3f6fd1`）になっている（IDセレクタはページ内で1箇所だけに効く） |
| `.card`の中にある段落と、`.card`の外にある段落を見比べる | `.card`の中の段落だけ灰色・小さめの文字になっている（子孫セレクタ`.card p`は`.card`の外の`<p>`には効かない） |

**正常な状態の見分け方**：4種類のセレクタがそれぞれ「全体」「クラスを持つ要素だけ」「IDを持つ1要素だけ」「特定の親の中だけ」という異なる範囲に効いているかで判断します。すべての段落が同じ見た目になってしまう場合は、セレクタの書き方（`.`や`#`の付け忘れなど）を疑ってください。

## 3. CSSとボックスモデル

> [example/03_box_model.html](example/03_box_model.html)

CSSでは、すべての要素が**箱（ボックス）**として扱われます。

```
┌─────────────── margin（外側の余白） ───────────────┐
│  ┌───────────── border（枠線） ─────────────────┐  │
│  │  ┌───────── padding（内側の余白） ─────────┐  │  │
│  │  │              content（中身）              │  │  │
│  │  └────────────────────────────────────────┘  │  │
│  └────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────┘
```

```css
.box {
    width: 200px;
    padding: 20px;
    border: 4px solid #3f6fd1;
    margin: 30px;
}
```

### `box-sizing: border-box`

デフォルト（`content-box`）では`width`は中身だけの幅を指し、実際の見た目は`padding`と`border`の分だけ広がります。`box-sizing: border-box`を指定すると、`width`に`padding`と`border`を含めて計算するようになり、サイズ計算が直感的になります。実務ではほぼ必ず指定します。

```css
.box-border-box {
    width: 200px;      /* paddingとborderを含めた幅がちょうど200pxになる */
    padding: 20px;
    border: 4px solid #d1723f;
    box-sizing: border-box;
}
```

### 実行方法

`example/03_box_model.html` をブラウザで開き、2つの箱の実際の幅の違いを確認してください。

### 動作確認：`box-sizing`の有無で幅がどう変わるか

| 確認する操作 | 確認したいこと |
|---|---|
| `example/03_box_model.html`をブラウザで開き、2つの箱を見比べる | どちらも`width: 200px`を指定しているのに、上の箱（`.box`）の方が下の箱（`.box-border-box`）より見た目の幅が広い |
| ブラウザの開発者ツールで`.box`の要素を選択し、幅（Box Model表示）を確認する | 実際の幅が`200px + padding(20px×2) + border(4px×2) = 248px`になっている（`content-box`は`width`に中身の幅しか含まない） |
| 同様に`.box-border-box`の幅を確認する | 実際の幅が指定通り`200px`ちょうどになっている（`box-sizing: border-box`により`padding`と`border`を含めて`200px`に収まる） |

**正常な状態の見分け方**：`box-sizing: border-box`を指定した箱だけ、指定した`width`と実際の見た目の幅が一致します。一致しない場合は`content-box`（デフォルト）のままになっている可能性があります。

## 4. Flexboxでナビゲーションを作る

> [example/04_flexbox.html](example/04_flexbox.html)

```css
nav {
    display: flex;
    align-items: center;
    gap: 16px;
}

.spacer {
    flex: 1;
}
```

### ポイント

| プロパティ | 説明 |
|---|---|
| `display: flex` | 子要素を横並びにする |
| `align-items: center` | 交差軸（縦方向）を中央揃えにする |
| `gap` | 子要素同士の間隔 |
| `flex: 1` | 余ったスペースをその要素が埋める。ナビの右寄せレイアウトによく使う |

`100_memo_api`のヘッダーの`nav`は、まさにこの`flex`の仕組みで組まれています。

### 実行方法

`example/04_flexbox.html` をブラウザで開いてください。

### 動作確認：ナビゲーションの並びと右寄せ

| 確認する操作 | 確認したいこと |
|---|---|
| `example/04_flexbox.html`をブラウザで開く | 「サイト名」「ホーム」「一覧」「ログイン」が縦にではなく**横一列**に並んでいる（`display: flex`の効果） |
| 「ホーム」「一覧」と「ログイン」の間隔を見る | 「ログイン」だけ右端に押し出されている（`.spacer`に`flex: 1`を指定し、余った幅を吸収しているため） |

**正常な状態の見分け方**：`nav`内の項目が横並びになり、かつ「ログイン」だけが右端に寄っていれば正常です。項目が縦に並んでしまう場合は`display: flex`が効いていません。

## 5. Gridでカードを並べる

> [example/05_grid.html](example/05_grid.html)

```css
.card-grid {
    display: grid;
    grid-template-columns: repeat(auto-fill, 150px);
    justify-content: center;
    gap: 16px;
}
```

### ポイント

| プロパティ | 説明 |
|---|---|
| `display: grid` | 子要素を格子状に並べる |
| `grid-template-columns: repeat(auto-fill, 150px)` | 幅150pxの列を、画面幅に収まるだけ自動的に並べる |
| `justify-content: center` | 列全体を中央寄せにする |

ブラウザの幅を変えながら開くと、列数が自動的に増減することを確認できます。`100_memo_api`のメモ一覧（カードグリッド）もこの仕組みです。

### 実行方法

`example/05_grid.html` をブラウザで開き、ウィンドウ幅を変えて列数の変化を確認してください。

### 動作確認：ウィンドウ幅に応じた列数の自動調整

| 確認する操作 | 確認したいこと |
|---|---|
| `example/05_grid.html`をブラウザで開く | カード1〜5が格子状（グリッド）に並んでいる |
| ブラウザのウィンドウ幅を広げたり狭めたりする | 幅に収まるだけの列数に**自動的に**増減する（`repeat(auto-fill, 150px)`により、列数を数値で固定していないため） |

## 6. レスポンシブ対応

> [example/06_responsive.html](example/06_responsive.html)

画面の幅（PC・タブレット・スマホ）に応じてレイアウトを切り替える仕組みを**レスポンシブ対応**と呼びます。CSSの**メディアクエリ**（`@media`）を使うと、「画面幅が◯◯px以下のときだけ、このCSSを適用する」という条件分岐ができます。

```css
.box-grid {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 16px;
}

/* 画面幅が768px以下になったら2列にする */
@media (max-width: 768px) {
    .box-grid {
        grid-template-columns: repeat(2, 1fr);
    }
}

/* 画面幅が480px以下になったら1列にする */
@media (max-width: 480px) {
    .box-grid {
        grid-template-columns: repeat(1, 1fr);
    }
}
```

### `<meta name="viewport">`

レスポンシブ対応には、`<head>`内に以下のタグが必須です。

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

このタグが無いと、スマホのブラウザは「PC用のページだろう」と判断してページ全体を縮小表示してしまい、メディアクエリが意図通りに機能しません。`width=device-width`で「実際の画面幅通りに表示する」ことを指定しています。

### ポイント

| 記法 | 説明 |
|---|---|
| `@media (max-width: 768px) { ... }` | 画面幅が768px以下のときだけ、中のCSSを適用する |
| ブレークポイント | スタイルが切り替わる幅の境目。`768px`＝タブレット、`480px`＝スマホ相当がよく使われる目安 |
| `<meta name="viewport" ...>` | モバイルブラウザに実際の画面幅通りに表示するよう伝える。無いとメディアクエリが正しく機能しない |

`100_memo_api`のメモ一覧も、`5. Grid`で学んだ`.card-grid`にこのメディアクエリを組み合わせて、タブレットで2列・スマホで1列に切り替えています。

### 実行方法

`example/06_responsive.html` をブラウザで開き、ウィンドウ幅を狭めながら列数が3列→2列→1列と変化することを確認してください（ブラウザの開発者ツールのデバイスツールバーを使うと、スマホ幅を再現できます）。

### 動作確認：ブレークポイントごとの列数切り替え

| 確認する操作 | 確認したいこと |
|---|---|
| `example/06_responsive.html`をPC幅のウィンドウで開く | 1〜6の箱が**3列**で並んでいる |
| ウィンドウ幅を狭め、768px以下にする（開発者ツールのデバイスツールバーで幅を指定すると確実） | 箱の並びが**2列**に切り替わる（`@media (max-width: 768px)`が発動） |
| さらに幅を480px以下まで狭める | 箱の並びが**1列**に切り替わる（`@media (max-width: 480px)`が発動） |
| `<head>`内の`<meta name="viewport" ...>`を一時的にコメントアウトして、スマホ幅相当（デバイスツールバー）で確認する（確認後は必ず元に戻す） | ページ全体が縮小表示され、実際のスマホ幅では2列/1列の切り替えが機能しなくなる（`viewport`タグの重要性を体感できる） |

**正常な状態の見分け方**：ウィンドウ幅を狭めるにつれて「3列→2列→1列」と**段階的に**変わることが正しい状態です。幅を変えても列数がずっと同じままの場合は、メディアクエリの`max-width`の値や`viewport`タグの設定ミスを疑ってください。

## 7. フォームの基本

> [example/07_form.html](example/07_form.html)

`<form>`と入力系タグを使って、お問い合わせフォームを作ります。ここで作るフォームは、`009_forms`の練習問題（お問い合わせフォームをFlask-WTFで作る）と**同じ項目構成**にしてあります。まずはPythonなしの見た目だけを作り、`009_forms`で実際に送信・バリデーションできるようにする、という流れです。

```html
<form method="post">
    <div class="field">
        <label for="name">お名前</label>
        <input id="name" type="text" name="name" required>
    </div>

    <div class="field">
        <label for="category">お問い合わせ種別</label>
        <select id="category" name="category">
            <option value="general">一般</option>
            <option value="support">サポート</option>
        </select>
    </div>

    <div class="field">
        <label for="message">メッセージ</label>
        <textarea id="message" name="message" rows="5" required></textarea>
    </div>

    <button type="submit">送信</button>
</form>
```

### ポイント

| タグ・属性 | 役割 |
|---|---|
| `<form method="post">` | 入力内容をまとめて送信する箱。`method`は送信方法（`get`/`post`） |
| `<label for="name">` | `<input id="name">`と`for`/`id`を一致させると、ラベルクリックで入力欄にフォーカスが移る |
| `<input type="text">` | 1行のテキスト入力 |
| `<input type="email">` | メールアドレス用。ブラウザが簡易的に形式チェックしてくれる |
| `<select>` / `<option>` | ドロップダウンの選択肢 |
| `<textarea rows="5">` | 複数行の入力欄。`rows`で表示行数を指定 |
| `<button type="submit">` | フォームを送信するボタン |
| `required` | 入力必須にするHTML標準の属性（本格的な検証は`009_forms`でPython側にも実装する） |

### CSSでのフォーム整形

```css
label {
    display: block;      /* ラベルを input の上に配置する */
    margin-bottom: 4px;
}

input[type="text"],
input[type="email"],
select,
textarea {
    width: 100%;          /* 横幅いっぱいに広げる */
    box-sizing: border-box;
    padding: 6px;
}
```

`label`を`display: block`にすると、ラベルと入力欄が縦に並びます。属性セレクタ（`input[type="text"]`）を使うと、同じ`<input>`タグでも`type`ごとに別のスタイルを当てられます。

### 実行方法

`example/07_form.html` をブラウザで開いてください（`method="post"`ですが送信先が無いため、送信ボタンを押すとブラウザ上でページが再読み込みされるだけです。実際に送信処理を行うのは`009_forms`です）。

### 動作確認：`required`によるブラウザ標準の入力チェック

| 確認する操作 | 確認したいこと |
|---|---|
| `example/07_form.html`をブラウザで開く | お名前・お問い合わせ種別・メッセージの3項目を持つフォームが、ラベルが入力欄の上に配置された縦並びのレイアウトで表示される |
| 「お名前」と「メッセージ」を**空欄のまま**送信ボタンを押す | ページ遷移せず、ブラウザ標準の吹き出し（「このフィールドを入力してください」等）が表示される（`required`属性による、Python側を介さないブラウザだけのチェック） |
| すべての項目に入力してから送信ボタンを押す | 吹き出しは出ず、ページが再読み込みされる（送信先が無いため、見た目上は元の空欄フォームに戻る） |

**正常な状態の見分け方**：`required`が付いた項目が空欄のときだけ、送信がブロックされてブラウザの警告吹き出しが出ます。空欄でも素通りしてしまう場合は`required`属性の付け忘れを疑ってください。なお、この`required`はブラウザ側だけのチェックであり、`009_forms`で学ぶPython側のバリデーション（`DataRequired()`など）とは別物である点に注意してください。

## 8. 演習：000_my_appのトップページを作る

> [challenge/](challenge/) — 演習の雛形 ｜ [challenge/answer/](challenge/answer/) — 完成例

ここまで学んだHTML/CSSの知識だけを使って、`000_my_app`のトップページ（メモ一覧画面）を静的なHTML/CSSで作ります。`001`〜`017`では、この**メモ帳アプリ**を少しずつ育てていきます。Flask・Jinja・Pythonは一切使いません。

### 作るもの

| 部分 | 内容 |
|---|---|
| `<header>` | `<nav>`の中に、サイト名と「メモ一覧」リンク |
| `<main>` | `class="card-grid"`の中に、メモカード（`class="card"`）を5つ |
| 各カード | カテゴリ（`<span class="tag">`）・タイトル（`<h3>`）・本文の冒頭（`<p>`） |
| `<footer>` | コピーライト表示 |
| レスポンシブ対応 | タブレット幅（768px以下）で2列、スマホ幅（480px以下）で1列になるようメディアクエリを追加する |

### 使うメモデータ

この先の章で繰り返し使う、以下の5件のメモを使います。

| タイトル | カテゴリ | 本文の冒頭 |
|---|---|---|
| 買い物リスト | 家事 | 牛乳、卵、パン、洗剤を買う。特売は火曜日まで。 |
| 企画会議メモ | 仕事 | 来週の企画会議の議題を整理する。新商品の販促案について。 |
| 読書メモ：銀河鉄道の夜 | 趣味 | 宮沢賢治の作品。銀河や星座の描写が美しい。 |
| アプリのアイデア | アイデア | 習慣トラッカーアプリを作る。毎日の記録をグラフで見せる。 |
| 旅行の持ち物リスト | プライベート | パスポート、充電器、常備薬を忘れずに。 |

画像は使いません（メモ帳アプリなので表紙画像は不要）。カテゴリは`<span class="tag">`で小さなバッジとして表示します。

### 進め方

1. `challenge/index.html`と`challenge/style.css`のTODOコメントに沿って実装する
2. ブラウザで開いて見た目を確認する（開発者ツールのデバイスツールバーでウィンドウ幅も狭めて、レスポンシブ対応まで確認する）
3. 一通り書けたら`challenge/answer/`の完成例と見比べる

### 動作確認：完成例（answer）と同じ構成になっているか

```bash
cd 002_html_css/challenge
python -m http.server 8000
```

ブラウザで`http://localhost:8000`（自分の実装）と`http://localhost:8000/answer/`（完成例）を開いて見比べます。

| 確認する操作 | 確認したいこと |
|---|---|
| `header`部分を見る | サイト名「メモ帳」と「メモ一覧」リンクが、`4. Flexbox`と同じように横並びで表示される |
| `main`部分を見る | 5件のメモカードが`5. Grid`と同じ格子状に並んでいる。各カードにカテゴリのタグ（丸いバッジ）・タイトル（`<h3>`）・本文の冒頭が表示される |
| `footer`部分を見る | コピーライト表示がページ下部にある |

**正常な状態の見分け方**：ヘッダー・カードグリッド・フッターの3つの領域がそれぞれ独立して正しく表示され、かつウィンドウ幅を狭めたときにカードの列数が完成例と同じタイミングで切り替われば完成です。カードが縦一列にしか並ばない、タグが四角いままなどの場合は、対応するセクション（5. Grid／2. セレクタ）の該当CSSクラスが抜けている可能性があります。

### ヒント

- ヘッダーの配色・角丸は「4. Flexbox」で学んだ`nav`のスタイルがそのまま使える
- カードの並びは「5. Grid」で学んだ`.card-grid`がそのまま使える
- カード自体（`.card`）は白背景・枠線・角丸・軽い影（`box-shadow`）を付けると「カードらしく」見える
- カテゴリのタグ（`.tag`）は`display: inline-block`・背景色・`border-radius`を大きめにすると丸いバッジらしく見える
- レスポンシブ対応は「6. レスポンシブ対応」で学んだ`@media (max-width: ...)`を`.card-grid`に追加すればよい

### この演習がこの先どうつながるか

作った静的ページは、この先の章で少しずつ`000_my_app`に機能を組み込んでいくための最初のパーツになります。

| 章 | この静的ページに何が加わるか |
|---|---|
| `004_flask_basic`〜 | Flaskでこのページを配信できるようにする |
| `006_jinja2` | `{% for %}`でメモカードをループ処理し、ハードコードだったメモデータをPythonの変数から埋め込む |
| `009_forms`〜`015_login` | メモ追加フォーム・ログイン機能・DB連携を追加する |
| `018_ownership_crud`〜 | 所有権付きCRUD・JavaScript・外部API連携・ロールベースの認可などが加わり、`000_my_app`が完成形の**メモ帳アプリ**（`100_memo_api`と同等）に育つ |
