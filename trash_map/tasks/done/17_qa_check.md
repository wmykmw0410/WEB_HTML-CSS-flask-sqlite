# 全体QAチェック（一区切り）

日付: 2026-08-29

## これは何をする作業か

ここまで実装した機能をひととおり動かし、アプリ全体として壊れているところがないかをまとめて確認する。新しい機能を追加する作業ではなく、既存の動作を検証する作業。

## 確認した手順

1. 主要なルート全て（`/`, `/map`, `/add`, `/thankyou`, `/list/<type_key>` × 5種類, `/trash/<id>`, `/trash/<id>/edit`, `/api/trashcans`, 静的ファイル一式）に順番にアクセスし、期待どおりのステータスコード（`200`）が返ることを確認した。
2. 存在しないID（`/trash/999999`, `/trash/999999/edit`）にアクセスし、正しく `404` が返ることを確認した。
3. `app.py` / `form.py` / `models.py` / `constants.py` をPythonの構文チェック（`py_compile`）にかけ、`static/js/*.js` の全ファイルをJavaScriptの構文チェック（`node --check`）にかけて、いずれも文法エラーがないことを確認した。
4. 「登録 → DB保存確認 → 詳細表示 → 種別/都道府県での絞り込み → 編集（写真は再アップロードせず維持） → `/api/trashcans` への反映」という一連の操作の流れを、テストデータを使って通しで確認した。確認後、テストデータはDBから削除した。
5. 写真未登録・郵便番号未入力のレコードでも、詳細ページ・一覧ページがエラーにならず表示されることを確認した（テンプレート内の `{% if %}` 分岐が正しく機能しているかの確認）。
6. データベースの実際のカラム構成（`PRAGMA table_info` で確認できる内容）と、`models.py` に書かれているカラム定義が完全に一致していることを確認した。

## 見つかった不具合と対処

- `static/trashcan.jpg`（もともと用意されていたサンプル画像。現在のコードからは参照されなくなっていた古いファイル）が、原因不明のままファイルシステムから消えていることに気づいた。作業開始時に取っておいたバックアップ（`trash_backup_20260829/`）から復元した。
- 今後同じような消失に気づけるよう、`static/` 配下のファイルは基本的にgitで管理下に置くことを推奨する（`tasks/todo.md` にも記載）。

## 結論

このチェックの結果、致命的な不具合は見つからなかった。残っている作業は全て `tasks/todo.md` に記載済みの項目（全件一覧ページ未実装、`/wrong` 未使用、Geolocation機能の実機確認など）のみだった。
