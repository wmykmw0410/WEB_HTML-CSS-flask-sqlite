# 関数・処理の解説

コードを読むときの参考用に、主な関数・クラスが「何を受け取り、何をするか」をまとめています。

## `app.py`（ルーティング＝どのURLでどの処理を行うかを決めるファイル）

**`inject_garbage_types()`**
- `@app.context_processor` が付いた特別な関数で、全てのテンプレート（HTMLファイル）から自動的に呼び出される。
- 戻り値の辞書 `{"garbage_types": GARBAGE_TYPES}` により、どのテンプレートでも `garbage_types` という変数でゴミ種別一覧が使えるようになる。これがあるおかげで、ヘッダーのハンバーガーメニュー（`base.html`）はどのページからでもゴミ種別を表示できる。

**`map_page()` / `index_page()`**
- どちらも `map/map.html`（地図ページ）を表示するだけの、同じ内容の関数。
- `/map` と `/`（トップページ）という2つのURLからアクセスできるようにするため、あえて2つに分けている。

**`add_page()`**
- `/add` に **GET** でアクセスすると、空の登録フォーム画面を表示する。
- **POST**（フォーム送信）されると `form.validate_on_submit()` が入力内容をチェックし、全項目OKなら `True` を返す。
- 写真がアップロードされていれば、安全なファイル名を作って `static/uploads/` に保存する。
- 入力内容から `TrashCan`（DBの1行に対応するPythonのクラス）のインスタンスを作り、データベースに保存する。
- 保存が終わったら `/thankyou` に redirect（転送）する。

**`thankyou_page()`**
- 「登録しました」のメッセージ画面を表示するだけの関数。

**`type_list_page(type_key)`**
- URLの一部を `type_key` という引数として受け取る（例: `/list/burnable` にアクセスすると `type_key = "burnable"`）。
- DBから該当する種類のゴミ箱だけを絞り込み、一覧表示用のテンプレートに渡す。
- URLの `?prefecture=...&city=...` の部分（クエリパラメータ）を使って、都道府県・市区町村でのさらなる絞り込みもできる。

**`detail_page(trash_id)`**
- URLの数字部分を `trash_id`（ゴミ箱のID番号）として受け取る（例: `/trash/1` → `trash_id = 1`）。
- `db.get_or_404(...)` で該当するIDのデータをDBから取得する。もし見つからなければ、自動的に404エラーページが表示される（アプリ側で分岐を書く必要がない）。
- ゴミの種類（`"burnable,can"` のようなカンマ区切りの英語キー）を日本語ラベルのリストに変換してからテンプレートに渡す。

**`edit_page(trash_id)`**
- 既存データを編集するための関数。**GET** なら現在の値がプリフィル（あらかじめ入力）された編集フォームを表示し、**POST** なら入力内容でDBを更新する。
- 写真は新しくアップロードされたときだけ差し替え、アップロードがなければ元の写真をそのまま残す。

**`api_trashcans()`**
- 地図のJavaScript（`map.js`）から呼ばれる窓口（API）。DBの全ゴミ箱データをJSON形式（プログラム同士がデータをやり取りするための共通フォーマット）で返す。人間がブラウザで見るページではなく、JSが読み取るためのデータを返す点が他のルートと異なる。

## `models.py`（データベースの構造を定義するファイル）

**`_utcnow()`**
- 現在時刻（UTC＝世界標準時）を返す小さな関数。DBに保存する日時の初期値・自動更新値として使われる。

**`TrashCan` クラス**
- データベースの `trash_cans` テーブルに対応するクラス。1つのインスタンス（実体）が、テーブルの1行＝1つのゴミ箱の情報に対応する。
- クラスの中の `db.Column(...)` の1行ずつが、テーブルの1つの列（カラム）に対応する。

**`full_address` プロパティ**
- `prefecture`（都道府県）・`city`（市区町村）・`address_line`（番地）の3つを1つの文字列に結合して返す。`item.full_address` と書くだけで住所全体をまとめて表示できるようにするための仕組み。

## `form.py`（入力フォームの項目とチェックルールを定義するファイル）

**`AddGarbageForm` クラス**
- 登録・編集フォームの入力項目と、それぞれのバリデーション（入力内容のチェックルール）をまとめたクラス。
- クラスの中の1つ1つのフィールド（`name`, `postal_code` など）が、HTMLの1つの入力欄（テキストボックス・セレクトボックス・チェックボックスなど）に対応する。

## `static/js/map.js`（地図ページの動きを制御するJavaScript）

**`distanceMeters(lat1, lng1, lat2, lng2)`**
- 2つの地点（緯度・経度）の直線距離をメートル単位で計算する関数。地球が丸いことを考慮した「Haversine公式」という計算式を使っている。

**`renderMarkers(items)`**
- ゴミ箱データの配列を受け取り、それぞれの位置に地図のピン（マーカー）を立てる関数。ピンをクリックすると詳細ページに遷移するようにイベントを設定している。

**`runNearbySearch(userLat, userLng)`**
- 現在地の緯度・経度を受け取り、選択中の半径以内にあるゴミ箱だけを地図に表示し、近い順の一覧を作る関数。「現在地から探す」ボタンを押したときに呼ばれる。

**`clearNearbySearch()`**
- 周辺検索の結果をリセットし、全てのゴミ箱を再び表示する関数。「クリア」ボタンを押したときに呼ばれる。

## `static/js/postal_lookup.js`（郵便番号からの住所自動補完）

- 郵便番号の入力欄からフォーカスが外れた（`blur`）タイミングで実行される処理。入力された数字が7桁であれば外部API（zipcloud）に問い合わせ、返ってきた都道府県・市区町村・町域名をフォームの各欄に自動入力する。

## `static/js/header.js`（ハンバーガーメニューの開閉）

- ハンバーガーボタンをクリックしたらメニューの表示/非表示を切り替え、メニューの外側をクリックしたら自動的に閉じる処理。
